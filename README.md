# termux-file-tidy

配置驱动的文件分类整理工具，供 Termux（Android）每天定时运行。

用一个纯文本配置描述「把哪个目录里、名字符合什么条件的文件，移动到哪个目录」，脚本读完配置后执行分类。

## 二、基本概念

配置由若干**规则块**组成，块之间用**空行**分隔。每个块描述一件事：

```
源目录 → 目标目录，条件是文件名包含某些字符串
```

例：

```conf
# 归并待 todo 图片
/DCIM/Screenshots
    /__我的文件/_归档文件/_待处理/代办事项
    com.microsoft.todos
```

读法：把 `/DCIM/Screenshots` 里名字中含 `com.microsoft.todos` 的文件，移动到 `/__我的文件/_归档文件/_待处理/代办事项`。

## 三、配置语法

### 3.1 注释

以 `#` 开头的行是注释，**整行忽略**；缩进的注释行同样忽略。

```conf
# 这是一条注释
    # 缩进里的注释也忽略
```

不支持行尾注释——`abc # xyz` 会把 `# xyz` 当成条件的一部分。

### 3.2 源目录（顶格书写）

以 `/` 开头、**不缩进**的行，是源目录。

- **可以连续写多行**，表示多个源目录共用同一套规则（逻辑上是「或」）
- 支持正则：`/Pictures/(教程)`、`/__我的文件/梗图.+`
- 路径一律视为相对手机存储根 `/storage/emulated/0`，即 `/DCIM` 实际是 `/storage/emulated/0/DCIM`

```conf
/Download/Seal
/Download/BILIBILIAS
    /__我的文件/收藏视频
```

### 3.3 目标目录（缩进书写）

源目录后面**缩进的第一行**、且以 `/` 开头，是目标目录。一个规则块只有一个目标。

- 目标不存在时自动创建
- 目标若位于源目录内部，会被自动排除，防止把刚移进去的文件再次扫到
- 支持 `.` 开头的相对写法吗？**不支持**，一律绝对路径

```conf
/DCIM/Screenshots
    /__我的文件/_归档文件/_待处理/代办事项
```

### 3.4 匹配条件（缩进书写）

目标目录之后，缩进书写的、**不是** `key: value` 形式的行，都是匹配条件。

- **多个条件之间是「或」**：命中任意一条即可
- 匹配方式是**子串匹配**（正则 `search`），不是整名匹配
- 匹配对象是**文件名**（不含目录路径）
- **一个条件都不写 = 匹配全部文件**

```conf
/DCIM/Camera
    /__我的文件/_归档文件/购买建议/购买建议-奶茶
    [0-9]{2}-.*(奶|茶)
```

`26-奶茶.jpg` 命中；`咖啡.jpg` 不命中。

条件按**正则**解释，因此：

- `com.microsoft.todos` 里的 `.` 是「任意字符」，实际会同时命中 `comXmicrosoftYtodos`
- 想精确匹配点号，应写 `com\.microsoft\.todos`
- `^` 锚定文件名开头，如 `^支付宝交易明细`

### 3.5 排除条件

缩进书写、以 `-` 或 `-:` 开头的行，表示排除；命中的文件跳过不动。

```conf
/Download
    /Download/new_dir
    [0-9a-z]{20,}
    - .+(jpg|txt)
```

上例：移动 20 位以上哈希名文件，但 jpg / txt 除外。

> ⚠️ `-` 与 `-:` 目前在不同年代的配置里混用，语义**待确认**（可能是「排除」也可能是「仅匹配」）。

### 3.6 动作指令

缩进书写、形如 `key: value` 的行是动作指令，控制「移动之后还要做什么」。

| 指令 | 说明 |
|---|---|
| `action: move` | 移动（**默认行为**，可省略不写） |
| `action: copy` | 复制而非移动，源文件保留 |
| `action: rename` | 只重命名，不移动 |
| `target: <值>` | 重命名 / 复制的目标名，支持变量和 `\1` 捕获组 |
| `.Prefix: <值>` | 重命名时加前缀 |
| `.replace: <正则>` | 重命名时把匹配部分替换掉 |
| `reg: <正则>` | 该段动作的筛选条件 |
| `command: <命令>` | 移动后执行 shell 命令，`{}` 代表文件路径 |
| `write_append: <路径>` | 向指定文件追加内容，支持 `\1` |
| `delete-empty: true` | 收尾时清空该源目录下的空文件夹 |

一个规则块里**可以写多段动作**，按出现顺序依次执行（见 `tasker_file_tidy.conf` 第 211-223 行：先 rename 再 copy）。

### 3.7 只有指令、没有目标的块

允许一个规则块只写源目录 + 指令，不写目标目录。典型用途是收尾清理：

```conf
# 删除空文件夹
/DCIM
	delete-empty: true
```

解析器按「缩进且以 `/` 开头且尚未设置目标」判定目标，其余缩进行按指令或条件处理。

## 四、变量与模板

用于 `target:`、`.Prefix:`、`command:`、`write_append:` 等位置。

| 变量 | 含义 | 示例输出 |
|---|---|---|
| `{ext}` | 扩展名（不含点） | `jpg` |
| `{name}` | 原文件名（不含扩展名） | `Screenshot_20260101` |
| `{timestamp}` | 时间戳 | `1735689600` |
| `{date:FMT}` | 格式化日期 | `{date:YYYYmmdd:HH}` → `2026010112` |
| `{Prefix:值}` | 文件名前加值 | `{Prefix:__}` → `__原文件名.jpg` |
| `\1` `\2` | 正则捕获组 | 取自同一段的条件正则 |

> `{date:...}` 的格式串含义**待确认**：是 `strftime` 风格（`%Y%m%d`）还是自定义风格（`YYYYmmdd`）。

## 五、执行流程

```
读取配置
  ↓
解析成规则列表（源、目标、条件、排除、动作）
  ↓
按源根扫描目录（递归）→ 收集候选文件
  ↓
逐个文件、按规则优先级试匹配，命中即执行动作
  ↓
全部规则跑完后，统一执行 delete-empty
  ↓
写日志 + 发送 Termux 通知
```

### 安全约定

- **只移动不删除**，`delete-empty` 仅删除空目录
- 目标同名文件**绝不覆盖**，自动改名为 `名称 (1).ext`
- 单个文件失败记录日志后继续，不中断整批
- 支持 `--dry-run` 只打印不执行

### 优先级（待确认）

多个规则可能匹配同一个文件。建议按「源路径越深越优先，同深度按配置文件行序」，而不是纯行序。

## 六、完整示例

```conf
# 归并待 todo 图片
/DCIM/Screenshots
    /__我的文件/_归档文件/_待处理/代办事项
    com.microsoft.todos

# 移动收藏视频
/Download/Seal
/Download/BILIBILIAS
    /__我的文件/收藏视频

# 重命名收藏视频
/__我的文件/收藏视频
    action: rename
    BV([0-9a-z]{4,})_
    .replace: BV([0-9a-z]{4,})_
    command: video-add-file {}
    write_append: \1/.voide.link

# 删除空文件夹
/DCIM
    delete-empty: true
```

## 七、待确认项

以下语义尚不明确，实现前需逐条确认：

1. `-` 与 `-:` 究竟是「排除」还是「仅匹配」
2. `.replace:` 的正则与上一行条件正则内容相同时，想表达什么
3. `{date:YYYYmmdd:HH}` 的格式串规则
4. `reg:` 与 `-:` 的区别
5. `write_append` 里 `\1` 的捕获组来源
6. 规则优先级按行序还是按源路径深度
7. 「按创建时间重命名」在 Android 上取 `st_ctime` 还是 `st_mtime`

## 八、Termux 定时运行

```bash
pkg install python termux-api
chmod +x ~/termux-file-tidy/tasker_file_tidy.py
termux-job-scheduler \
  --script ~/termux-file-tidy/tasker_file_tidy.py \
  --period-ms 86400000 \
  --persisted true \
  --battery-not-low false
```

`--persisted true` 保证重启后计划仍生效。
